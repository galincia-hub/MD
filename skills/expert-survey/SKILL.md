# 전문가 설문 제작 Skill

## 이름
전문가 설문 제작

## 목적
방선투어, 인스펙션, 팸투어, 파트너 평가, 상품 설명회 등에서 전문가·파트너 대상 웹 설문을 빠르게 만들고, 응답 수집부터 분석·보고서 작성용 데이터까지 한 번에 준비한다.

현재 기준 레퍼런스는 `adora-ship-visit-0929/survey/`의 **ADORA MEDITERRANEA 방선투어 전문가 비교평가 V1**이다.

---

## 호출 예시
사용자가 아래처럼 요청하면 이 스킬을 적용한다.

- `전문가 설문 만들어줘`
- `방선 설문 새로 만들어줘`
- `인스펙션 설문 만들어줘`
- `아도라 설문 구조로 새 설문 만들어줘`
- `이번에는 MSC 벨리시마 대상으로 같은 방식으로 만들어줘`

짧은 요청이라도 현재 프로젝트 맥락에서 대상·목적이 충분히 분명하면 불필요한 질문을 반복하지 않는다.

---

## 기본 원칙

1. **질문의 질이 우선**이다. 기술 구현부터 시작하지 않는다.
2. 대상자의 전문성에 맞춘다. 일반 소비자 만족도 문항을 전문가 설문에 그대로 쓰지 않는다.
3. 설문 목적이 선사·파트너 개선 요청이라면 질문의 70~80% 이상을 `현 상태 / 강점 / 약점 / 개선사항`에 집중한다.
4. 비교 대상이 있으면 비교기준을 명확히 한다. 예: `COSTA SERENA = 10점`, 0~20점 비교척도.
5. 직접 경험하지 못한 항목은 `평가하기 어려움(경험하지 못함)`을 허용하고 **평균 계산에서 제외**한다.
6. 관련 객관식 점수와 주관식 원문은 분석 화면에서 **같이 본다**.
7. 주관식 원문은 요약으로 대체하지 않고 원문을 보존한다.
8. 개인정보가 필요하지 않으면 받지 않는다. 소속은 필요 최소 범주의 `참여 구분`으로 받는다.
9. 기술은 단순하게 유지한다. **브라우저 자동화나 Apps Script를 먼저 선택하지 않는다.**
10. 설문 화면, 저장, 리포팅을 각각 분리하되 사용자가 관리해야 할 시스템은 최소화한다.

## 권장 작업 순서

### Phase 1. 설문 목적과 대상 정의
아래 5가지만 먼저 확정한다.

- 설문 목적
- 응답 대상
- 비교 기준 또는 평가 기준
- 결과를 누구에게 전달할지
- 결과로 어떤 의사결정을 할지

정보가 현재 대화에 이미 있으면 다시 묻지 않는다.

### Phase 2. 질문안 먼저 제시
개발 전에 채팅에서 전체 질문을 먼저 보여준다.

질문은 다음 구조를 기본으로 한다.

- 인트로 + 참여 구분
- 영역별 점수형 질문
- 영역별 관련 주관식
- 종합평가
- 가장 좋았던 점
- 우선 개선사항
- 향후 항차·운영 질의/건의

사용자가 질문 방향을 수정하면 질문을 먼저 확정한 뒤 개발한다.

### Phase 3. 웹 설문 생성
기본 UI 원칙:

- 모바일 우선
- 카카오톡 인앱 브라우저에서 사용 가능
- 인트로/참여구분 1페이지 + 전체 설문 1페이지, 총 2페이지
- 상위 카테고리는 파스텔톤으로 구분
- 점수 슬라이더는 현재 점수를 크게 표시
- 미선택 점수는 `-`
- 선택 점수는 강조색 + 굵게
- `평가하기 어려움(경험하지 못함)` 제공
- 긴 주관식은 글자수 표시
- 필수 문항은 실제 제출 검증과 화면 문구를 반드시 일치시킨다.

### Phase 4. 저장
기본 저장 구조는 가장 단순한 방식을 우선한다.

**기본값: GitHub Pages → 숨은 Google Form → Google Sheet**

- Google Form에는 `payload` 장문형 1문항만 둔다.
- 웹 설문에서 전체 응답을 JSON 1줄로 전송한다.
- Google Sheet에는 `타임스탬프 / payload` 원본을 보존한다.
- Apps Script는 단순 Form 저장으로 해결되지 않을 때만 사용한다.
- TinyFish 등 브라우저 자동화는 저장 기술의 필수 요소가 아니다.

권장 payload:

```json
{
  "version": "YYYY-MM-DD-v1",
  "ref": "",
  "affiliation": "판매여행사",
  "surveyType": "C",
  "answers": {
    "O01": 12,
    "F01": "NA",
    "R02": "주관식 원문"
  },
  "submittedAt": "ISO-8601"
}
```

### Phase 5. 결과 시트
원본과 분석 화면을 분리한다.

필수 탭:

- `설문지 응답 시트1` : 원본 payload
- `응답 보기` : 응답자 1명 = 1행, JSON 해제
- `요약` : 기초 통계
- `문항별 보기` : 질문 중심 분석
- `보고서용 복사` : AI/Word에 바로 붙여넣는 텍스트

`문항별 보기`에서는 반드시 다음을 보여준다.

- 평균 /20
- 비교 기준 대비 차이
- 유효응답수
- 평가안함 수
- 최저/최고
- 참여 구분별 평균
- 관련 주관식 원문

관련 주관식은 해당 응답자의 관련 점수와 함께 표시한다.

예:

`[판매여행사 | 공연 12 · 바/라운지 10 · 수영장 평가안함 · 식당 9] 공연장 동선 개선 필요`

### Phase 6. 보고서용 복사
보고서용 복사 화면은 반드시 **질문 순서대로 점수와 관련 주관식을 함께** 배치한다.

권장 순서:

1. 응답수 / 기준
2. 참여 구분별 응답수
3. 선박 전반
4. 공용시설 + 공용시설 주관식
5. 음식·서비스 + 관련 주관식
6. 종합평가 + 가장 좋았던 점
7. 우선 개선사항
8. 향후 항차 질의·건의
9. 참여 구분별 평균점수

AI 보고서 생성용 프롬프트도 함께 둔다.

## 비교척도 기본 규칙
비교형 전문가 설문의 기본 예시는 다음과 같다.

- 0~9점: 비교 대상보다 상대적으로 아쉬움
- 10점: 비교 대상과 비슷함
- 11~20점: 비교 대상보다 상대적으로 우수함
- `평가하기 어려움`: 평균에서 제외

설문 화면에서 매 문항마다 기준 설명을 반복하지 않고 페이지 상단에 공통 가이드를 둔다.

## 배포 문구
설문 완성 시 카카오톡용 배포문도 함께 준비한다.

포함 요소:

- 참석 감사
- 설문 취지
- 왜 응답자의 전문 의견이 중요한지
- 결과를 어디에 활용하는지
- 적극 참여 요청
- 함께 참석한 주변 인원에 대한 참여 독려
- 설문 링크
- 응답 마감일

## 하지 말아야 할 것

- 단순한 저장 문제를 복잡한 서버/자동화 문제로 확대하지 않는다.
- Apps Script, 별도 서버, 브라우저 자동화를 기본값으로 선택하지 않는다.
- 질문을 확정하기 전에 디자인·배포를 먼저 만들지 않는다.
- `평가하기 어려움`을 0점 처리하지 않는다.
- 주관식 의견만 따로 모아 객관식 점수와 맥락을 분리하지 않는다.
- 원본 응답을 요약본으로 덮어쓰지 않는다.
- 응답자에게 불필요한 이름·회사명을 강제로 요구하지 않는다.
